# 課堂觀察清單（選用）

每組建議一位操作、一位核對來源、一位記錄；每章交換角色。

各章操作完成後，可直接參考畫面中的報告、規則及工具紀錄討論。需要筆記時，可用文字或截圖記錄「我改了什麼，如何判定生效」，並區分真實官網資料與教學採購情境。

| 實作 | 可觀察的內容 | 討論問題 |
|---|---|---|
| L01 | 第一份比較表、一項問題 | TW 的 32 GB 保固可否從 US 補上？ |
| L02A | SKILL.md、前後報告、規則修改觀察 | 新規則是否被採用，產品事實有沒有被改寫？ |
| L02B | MCP 工具紀錄、正常及 not_found 報告 | 真正走 MCP 嗎？查不到時有沒有編造資料？ |
| L03 | 直接下載PDF、Chroma筆數、向量模型、搜尋片段與頁碼 | 文件向量與問題向量各做什麼？手冊能證明台灣報價嗎？ |
| L04 | 計畫、證據、需求矩陣、修訂紀錄、停止原因 | Dell 200V能升級嗎？台灣SKU、服務權益、報價還缺什麼？ |
| L05 | 原 Thread、中斷狀態、前後 log、唯一取證筆數、報告 | HP是否重查？Lenovo為什麼進兩次卻只有一筆？ |
| L06 | 來源快照、RFQ前後草稿、決定與本機存檔回執 | 舊hash能放行新稿嗎？本機存幾筆？實際寄幾封？ |

可選擇口頭說明四件事：一個待確認、一個錯誤分支、一個恢復證據、一個授權邊界。

不要交 API Key、個人信箱、真實客戶資料或整個虛擬環境。通知對象使用 `.invalid` 測試地址。老師示例不是同學實際執行證據；未完成請標示未完成。
