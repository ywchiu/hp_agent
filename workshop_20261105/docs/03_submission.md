# 同學的成果清單

每組建議一位操作、一位核對來源、一位記錄；每章交換角色。

建立自己的成果資料夾，內容可用 Markdown、JSON 與截圖。Colab 使用最後一格下載 ZIP。

第一天下午先交 L01、L02A、L02B 三份成果 ZIP：兩次報告、問題／規則、工具紀錄，並各寫一句「我改了什麼，如何判定生效」。第二天項目等第二天課程再做。

| 實作 | 應交內容 | 同學互相驗收的問題 |
|---|---|---|
| L01 | 第一份比較表、一項問題 | TW 的 32 GB 保固可否從 US 補上？ |
| L02A | SKILL.md、前後報告、規則修改觀察 | 新規則是否被採用，產品事實有沒有被改寫？ |
| L02B | MCP 工具紀錄、正常及 not_found 報告 | 真正走 MCP 嗎？查不到時有沒有編造資料？ |
| L03 | 問題、取回片段、來源 ID、適用性 | 為什麼不能採用舊版或 US 文件？ |
| L04 | 計畫、證據、需求矩陣、修訂紀錄、停止原因 | 哪個證據支持記憶體？到府服務仍缺什麼？ |
| L05 | 原 Thread、中斷狀態、前後 log、唯一取證筆數、報告 | Dell／Lenovo 是否重查？ASUS 為什麼進兩次卻只有一筆？ |
| L06 | 兩週快照、事件、v1/v2 草稿、決定與測試回執 | 舊核准能否放行新版本？重跑增加幾筆通知？ |

口頭演示四件事：一個待確認、一個錯誤分支、一個恢復證據、一個授權邊界。

不要交 API Key、個人信箱、真實客戶資料或整個虛擬環境。通知對象使用 `.invalid` 測試地址。老師示例不是同學實際執行證據；未完成請標示未完成。
