# 講師帶課手冊與答案

本版不重排 357 頁原簡報。第一天下午直接從 L01 開始；L02 拆成 Skill、MCP 兩份 Colab。第二天 L03–L06 使用120台企業採購案與真實官方來源，入口見 [第二天教材](../day2/README.md)。以下時間是實作建議。

第一天下午先開 [課堂入口](../day1/README.md)：每份先看狀態圖，再帶同學照五步操作。示範時讓底層程式保持收起，重點是改哪段中文、如何請 AI 修改、如何核對。

老師提供 Key，確認該 Key 可使用指定模型與課堂用量。Colab 第 2 步在執行時輸入，不把真實 Key 放進 GitHub 或投影片。模型會被實際呼叫；模擬產品資料不等於假模型。每份兩次研究，每次最多六次模型呼叫，反覆重跑會增加用量。

## 課前演練

- 先用一個乾淨虛擬環境跑測試；下載 ZIP 當作沒有 GitHub／網路來源時的教材備份。
- 在實際帳號先跑第一天下午三份 Colab：Key 輸入、模型工具呼叫、修改與 MCP。
- 預先跑一份 L05 中斷現場，再準備另一個新資料夾現場示範；不要用已完成的 Thread 重跑 start。
- 確認第二天所有核准結果只存本機 outbox，畫面顯示目前狀態與草稿。不要把教材測試寄件器說成正式寄送。

第二天依目前預設最多約23次模型回應（L03兩次回答、L04最多17次、L05三次、L06一次）；L03另有文件／問題embedding，重跑或改題另計。L04兩輪最多5個子題，每題發出1個搜尋請求並保留最多2個官方候選，工具實際執行次數以API紀錄為準；單輪可降低課堂時間。搜尋工具用量另計，官方站可能封鎖，讀取失敗須保留，不能用摘要冒充原文。

L03：下載HP手冊、Lenovo PSREF與Dell型錄，建立三品牌競品證據庫。確認HP封面「14 inch Notebook AI PC」型號，不當成所有Next Gen AI配置。下載後顯示頁數／片段／向量維度，將向量、原文與頁碼存入Chroma，顯示collection、庫內筆數及已存範例。先只跑搜尋，停下來帶學生看片段ID、檔名、頁次、分數與完整原文；核對型號後，再按下一格生成三品牌比較表，對照剛才的證據與回答引用；報價／交期／台灣三年到府須保留缺口。文件向量可重用，每次新問題仍呼叫embedding及回答。引用ID存在不代表原文支持，圖片頁需OCR。

L04：參考四月PDF 195–205頁與 `code/05_Deep_Research_Agent.ipynb` 的研究迴圈。前10分鐘先看狀態圖與3個跨品牌子題，20分鐘看搜尋／原文帳本與Reader，15分鐘讀初稿／Critic，20分鐘看第二輪計畫與新增證據，最後10分鐘比較報告與限制。Planner與Critic後以LangGraph記憶體checkpoint暫停，下一格續跑；不是L05的持久化恢復。所有角色共用課堂模型，輸入與職責分開。

Critic區分 `public_gaps`、`supplier_questions`、`conflicts`；完整性分數不是準確率。可補查且未達上限才重排計畫；沒有新證據、沒有新問題、只剩供應商事項或已達上限就交報告。不要強迫每次出現兩輪，更不要將未確認條件寫成通過。`trace.json`保留各輪子題、原文、筆記、初稿與評審。先核對WEB來源，再對照第一輪／最終稿的改變。看完報告再重跑顯示／完成格，模型回應紀錄應維持相同數量。

L05：中斷後checkpoint只有HP，帳本有HP／Lenovo；恢復log是HP/Lenovo/Lenovo(reused)/Dell，唯一結果三筆。兩個Python程序實際讀寫同SQLite。若API完成後、提交結果前失敗，仍可能重呼叫模型；不將結果去重誇大為所有外部操作恰好一次。

L06：前10分鐘真實PDF觀察與基準；15分鐘比較模擬兩週報價（40,000→34,000為−15%，39,000為−2.5%）、不同SKU與讀取失敗；15分鐘讀RFQ、加中文條件與新舊指紋；10分鐘先wait、再由學員approve或reject並填理由；最後10分鐘看三條獨立分支與再次執行。主審核不會被分支演練替代。所有價格演練明確標為模擬，真實產品規格仍來自官方片段；不以PDF指紋推定降價。新版附件／正文會改指紋，事件條件或來源指紋變動另建事件；僅重跑同事件不重複存檔。真實PDF每次觀察留歷史，失敗不覆蓋有效基準。

本機核准只是保存本機草稿，沒有正式寄信、排程、審核者身分與權限系統。正式上線另需授權驗證、有效期限與外部回執；不能把課堂的本機防重複說成郵件投遞恰好一次。

## D01｜PDF 1–40：完整交辦任務單

請每組寫五欄：Goal（成果）、Context（資料）、Constraints（限制）、Output（格式）、Acceptance（驗收）。例：比較台灣兩種 DemoBook 配置，使用教材 JSON；不能跨市場補值；交表格與缺口；核對每筆來源。

PDF 40 的擅自降價案例：分別討論「成交效果」與「有無授權」。要求同學寫出可自動讀取、可產草稿、必須核准三類操作；不要把成交通過當作越權合理化。

## D02｜PDF 41–94：企業與權限討論

PDF 82–88：給一段夾帶指令的外部郵件，要求分出產品資訊與操作要求。參考答案：讀取產品資訊不會自動開出外傳內部檔案的權限；重要承諾前先核對對象、版本與證據。

PDF 93：用前述五欄任務單改寫同學原本模糊的請求。請同學彼此只看任務單，判斷能否驗收。

## D03｜PDF 95–124：Prompt／Context／Harness

這段講概念後直接進 L01，不安排獨立環境檢查作業。

讓同學把本專案分成：prompt＝本輪問題；context＝產品與企業片段；harness＝工具、流程、checkpoint、上限及測試。請勿用單一長 prompt 取代需要程式驗證的副作用控制。

PDF 141／171 的討論：要求提供安全機制未被關閉的證據及變更範圍；不能為了 Demo 通過刪除核准或來源檢查。

## D04｜PDF 300–306：恢復與授權

PDF 305：通知可能已寄出，系統卻當機。先查外部結果、同一操作識別與回執；未知時交人工確認，不能把 checkpoint 沒完成當作外部效果沒發生。

## D05｜PDF 349–350：轉用其他任務

讓每組將設計套用到供應商報價、專案待辦或法規追蹤，寫出設定、有效基準、狀態、觸發條件與人保留的決定。主管核准後發現新證據，也要暫停失效操作並重新核對，不擅自改已核准內容。

## D06｜PDF 351–357：交付與上線責任

需要課堂討論時，可參考[觀察清單](03_submission.md)選擇口頭說明的內容。課後上線另外指派排程、儲存、備份、資料維護、失敗處理與成本負責人。不要把手動來源檢查稱為已部署的持續追蹤。

## 講師評量（每項 0–2 分，共 10 分）

1. 正確比較範圍與配置。
2. 來源可回查且未知保留。
3. 工具呼叫與角色交接有紀錄。
4. 中斷恢復與去重有證據。
5. 審核、版本與副作用控制正確。

0＝未完成；1＝產物有但證據不足；2＝可現場指出對應輸入、過程與結果。不得只憑報告文字流暢給滿分。
